## Входные данные и единицы

| Поле                                          | Единица | Обязательное                     | Допустимо                             |
| --------------------------------------------- | ------- | -------------------------------- | ------------------------------------- |
| Длина комнаты `L`, ширина `W`                 | м       | да                               | 0,1–100                               |
| Высота стен `H`                               | м       | да                               | 0,5–10                                |
| Ширина рулона `w`                             | м       | да                               | 0,1–3                                 |
| Длина рулона `R`                              | м       | да                               | 0,5–100                               |
| Количество окон / дверей                      | шт.     | нет (пусто = 0)                  | целое 0–50                            |
| Ширина и высота окна / двери                  | м       | если количество > 0              | ≥ 0,1; ширина ≤ max(L, W); высота ≤ H |
| Раппорт `r`                                   | см      | нет (пусто = 0)                  | 0–200                                 |
| Запас на подрезку `t` (на полосу, верх + низ) | см      | нет (пусто = 0), по умолчанию 10 | 0–100                                 |
| Цена рулона                                   | ₽       | нет                              | 0–1 000 000, не точнее копейки        |

Все окна считаются одинаковыми, все двери — тоже. Суммарная ширина проёмов не может превышать периметр.

## Стоимость

Общее для всех калькуляторов (D-033, `src/lib/cost.ts`): цена — как на ценнике, необязательна, 0–1 000 000 ₽,
не точнее копейки; внутри — целые копейки (`round(цена · 100)`), произведения — точно (`BigInt`); сумма больше
2⁵³ − 1 копеек (~90 трлн ₽) — ошибка у поля цены, а не неточное число. Стоимость — по тому, что покупается
(целые упаковки), а не по точному расходу. Деньги — `formatRubles`: пробелы между разрядами, копейки только
ненулевые. Цена не запоминается между калькуляторами.

Стоимость `= рулоны · цена рулона`; в результате — «Стоимость ≈ 11 699,10 ₽» и «9 рулонов × 1 299,90 ₽» под
«К покупке». До версии 0.18 цена точнее копейки молча округлялась; теперь это ошибка у поля, как во всех
калькуляторах.

## Три разных величины

Калькулятор показывает их отдельно и не смешивает:

1. **Теоретическая площадь** — площадь стен `P·H`, площадь проёмов `Σ count·a·h` и их разность.
   Справочная величина: **на число рулонов не влияет**, потому что обои расходуются полосами, а не площадью.
2. **Расчётная потребность в целых полосах** — полосы по стенам, сэкономленные на проёмах полосы,
   полосы на полную высоту, число полос из рулона.
3. **Раскладка по рулонам** — какие полосы и короткие куски из каких рулонов вырезаются. Калькулятор строит
   **гарантированно выполнимый план** для худшего неизвестного случая (положение проёма, высота подоконника,
   фаза рисунка в начале рулона). Это не точная модель реальной раскладки: для неё не хватает исходных данных.

## Единая система единиц

Все размеры переводятся в **целые миллиметры** (`Math.round`), деление с округлением — целочисленное.
В двоичной арифметике `4.2 / 0.7 = 6.000000000000001`, и округление вверх дало бы 7 полос вместо 6
(тест «стена 4,2 м при рулоне 0,7 м»). Точность ввода — 1 мм.

## Алгоритм (версия 2)

1. **Полосы по стенам**: `N = 2·⌈L / w⌉ + 2·⌈W / w⌉`. Каждая стена клеится от угла; обрезок угловой полосы
   на соседнюю стену не переносится.
2. **Длина полосы на стене** `b = H + t`. **Шаг расхода рулона на полосу** `S = b` без раппорта
   и `S = ⌈b / r⌉·r` с раппортом: соседние полосы начинаются с одной и той же точки рисунка.
   Подрезка входит в `b` один раз, раппорт округляет `b` — двойного запаса нет.
3. **Подгонка в начале рулона** `s = r` (без раппорта `s = 0`): фаза рисунка в начале рулона неизвестна,
   на совмещение уходит до одного раппорта.
4. **Полос из рулона**: `k = ⌊(R − s − b) / S⌋ + 1`, если `s + b ≤ R`, иначе `k = 0` — ошибка ввода
   «полоса длиннее рулона». Последней полосе из рулона хвост до следующей фазы не нужен, поэтому `+ 1`.
   Без раппорта формула совпадает с `⌊R / b⌋`.
5. **Экономия на проёме** шириной `a`: `e = max(0, ⌊a / w⌋ − 1)` — столько полос гарантированно целиком
   попадает в проём при любом его положении относительно стыков.
6. **Короткие куски** — по одному на каждую сэкономленную полосу:
   - дверь: `(H − h) + t`; с раппортом — округление вверх до кратного `r` (кусок начинается с той же фазы,
     что и полосы);
   - окно: `(H − h) + 2t` (куски над и под окном считаются вместе); с раппортом — округление вверх до кратного
     `r` **плюс ещё один `r`**: фаза нижнего куска зависит от высоты подоконника, которая не вводится;
   - если кусок не короче шага полосы `S`, экономии на этом проёме нет — колонка остаётся полной полосой;
   - если `H = h`, кусок не нужен.
7. **План с проёмами**: `N − Σe` полных полос → `n₁ = ⌈(N − Σe) / k⌉` рулонов. Остаток каждого рулона,
   совмещённый с фазой рисунка, — `R − s − m·S` (m — полос из него, не меньше 0). Куски раскладываются
   по остаткам «первым подходящим» от длинных к коротким; не поместившиеся — в новые рулоны ёмкостью `R − s`.
8. **План без проёмов**: `⌈N / k⌉` рулонов — выполним всегда.
9. **Итого** — меньший из двух планов (проёмы никогда не увеличивают расход). **Стоимость** = рулоны × цена,
   в копейках.

## Что гарантируется и что нет

При допущениях ниже план **достаточен при любом** положении проёмов на стене, любой высоте подоконника и любой
фазе рисунка в начале рулона. Это проверено перебором (`wallpaper.audit.test.ts`).

Допущения:

- комната прямоугольная, высота стен одинаковая; ниши, выступы и короба не учитываются;
- поклейка каждой стены начинается от угла (если начинать от окна, на стене может понадобиться на полосу больше);
- каждый проём целиком на одной стене, проёмы не перекрываются; окна одного размера, двери тоже;
- рисунок с прямой стыковкой; для **смещённой стыковки** (на этикетке «64/32» со значком смещения) отход
  может быть больше — модель это не учитывает;
- длина рулона соответствует этикетке, брака нет, полосы режутся без ошибок.

Калькулятор **намеренно** не учитывает экономию, которую нельзя гарантировать без дополнительных данных:
перенос обрезка угловой полосы на соседнюю стену (до 1 полосы на стену), удачное положение проёма
по стыкам, обрезки от полос, вырезанных вокруг проёмов. Поэтому реальный расход у аккуратного мастера
может быть меньше расчётного. Округлений «на всякий случай» сверх этих правил нет.

Калькулятор **не проверяет**, помещаются ли все проёмы на стены по отдельности: проверяются только ширина
каждого проёма (≤ самой длинной стены) и сумма ширин (≤ периметра). Для физически невозможного набора
проёмов результат не имеет смысла.

## Аудит (этап 2.1)

Аудит проверял модель версии 1 независимо от её тестов: перебором в миллиметрах (фазы рисунка, положения
проёмов, высоты подоконника), сравнением периметра и постенного счёта и поиском случаев, где проёмы
увеличивают расход (1600 сочетаний).

на стене); куски для сэкономленных полос учитываются все; раскладка «первым подходящим» выполнима по построению
(может быть не оптимальной — тогда в запас).

### Проверки против независимых симуляторов

`wallpaper.audit.test.ts` содержит симуляторы, которые не используют формулы калькулятора:

- **рулон**: пошаговая нарезка полос с подгонкой фазы для каждой из `r` возможных фаз начала рулона —
  число полос из рулона совпадает с формулой на 3 длинах рулона × 18 высотах × 8 раппортах;
- **стена**: наклейка полос от угла по одной — совпадает с постенным счётом (1000+ сочетаний, рулоны 0,53, 0,7, 1,06 м);
- **проём**: минимум по всем положениям проёма (с шагом 1 мм) — экономия калькулятора никогда не больше;
- **окно с раппортом**: худшее потребление по всем высотам подоконника — кусок калькулятора никогда не короче;
- **монотонность**: расход не убывает с ростом высоты и длины комнаты и не растёт с длиной рулона;
- **проёмы**: с проёмами рулонов не больше, чем без них.
