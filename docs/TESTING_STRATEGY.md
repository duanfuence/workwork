# Стратегия тестирования

## Уровни

| Уровень   | Инструмент                                          | Где                           | Когда запускается                       |
| --------- | --------------------------------------------------- | ----------------------------- | --------------------------------------- |
| Типы      | `astro check` (TypeScript strictest)                | весь проект, включая `.astro` | `npm run typecheck`, CI                 |
| Линтер    | ESLint 10 + typescript-eslint + eslint-plugin-astro | весь проект                   | `npm run lint`, CI                      |
| Формат    | Prettier + prettier-plugin-astro                    | весь проект                   | `npm run format:check`, CI              |
| Unit      | Vitest 5                                            | `src/**/*.test.ts`            | `npm test`, CI                          |
| Сборка    | `astro build`                                       | —                             | `npm run build`, CI                     |
| Интерфейс | Playwright 1.63 + Chromium (headless shell)         | `scripts/ui-check.mjs`        | `npm run build && npm run ui:check`, CI |

`npm run check` запускает первые пять уровней в том же порядке, что и CI; затем CI ставит браузер
(`npx playwright install --with-deps --only-shell chromium`) и запускает `npm run ui:check`.

Проверка качества тестов калькулятора: внесённые вручную ошибки (без «− 1» в экономии на проёмах,
без раскладки кусков, деление дробей в метрах) приводят к падению тестов.

Правило аудита: ошибку сначала воспроизводит тест, затем исправляется код. Ожидания в существующих тестах
меняются только при осознанном изменении модели — с пересчётом вручную и записью «было → стало»
в документе калькулятора.

Playwright — devDependency с точной версией 1.63.0 (`npm ci`), браузер — отдельной командой: в CI

Предпросмотр запускается с `--ignore-lock`: в переднем плане, без lock-файла, останавливается вместе со скриптом
(см. `DECISIONS.md`, D-020).

## Правила для калькуляторов

- Формула — чистая функция в `src/lib/calculators/`, тест рядом.
- Минимум: 2–3 контрольных примера, посчитанных вручную и записанных в тесте с пояснением;
  граничные значения (ноль, очень большие размеры, проёмы больше стены); округление вверх до целых упаковок.
- Недопустимый ввод — явная ошибка/сообщение, а не `NaN` в интерфейсе.
- Тесты не подгоняются под текущий результат кода — ожидаемые значения считаются независимо.

## Чего нет и почему

- Нет e2e в CI: потребуется установка браузеров в CI — добавить на этапе 4. Пока UI-проверку запускать
  вручную перед каждым коммитом, меняющим интерфейс.
- Нет визуальной регрессии и Lighthouse — этап 4.
