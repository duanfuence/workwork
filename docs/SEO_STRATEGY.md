# SEO-стратегия

## Модель

Каждый калькулятор — отдельная статическая страница под конкретный поисковый запрос
(«калькулятор обоев», «сколько ламината нужно на комнату»). Главная и (позже) страницы категорий
собирают ссылки на калькуляторы. Основные поисковые системы аудитории — Яндекс и Google.

## Принятые решения

- Статическая генерация: весь текст и метаданные — в HTML без выполнения JS.
- URL на транслите, в нижнем регистре, со слэшем в конце: `/kalkulyatory/<slug>/`
  (`oboi`, `laminat`, `kraska`, `plitka`, `shpaklevka`, `shtukaturka`). URL не меняется после публикации.
- `trailingSlash: 'always'` и `build.format: 'directory'` — один канонический вид адреса.
- Метаданные калькулятора хранятся в каталоге: `seo.title` (≤ 70 символов, проверяется тестом),
  `seo.description` (≤ 160), `seo.keywords` — целевые запросы (используются для семантики и поиска по сайту;
  `<meta name="keywords">` не выводится — поисковики его не учитывают).
- `BaseLayout`: `lang="ru"`, `charset utf-8`, `title`, `description`, `viewport`, `theme-color`,
  Open Graph (`og:type`, `og:locale`, `og:site_name`, `og:title`, `og:description`).
- Адрес сайта — переменная окружения `SITE_URL` при сборке (`https://домен` без пути, параметров и якоря;
  проверка — `src/lib/site-url.ts`, неверное значение останавливает сборку с объяснением). Пока домена нет,
  `SITE_URL` не задаётся, и сайт собирается без всего, что требует абсолютного адреса.
- С `SITE_URL`:
  - `canonical` и `og:url` — канонический адрес страницы (`src/lib/seo.ts`: со слэшем на конце, без параметров
    и якоря); у страниц с `noindex` (404) их нет;
  - `og:image` — `/og.png` (1200 × 630), `og:image:type`, `og:image:width`/`height`, `og:image:alt`,
    `twitter:card=summary_large_image`;
  - JSON-LD `BreadcrumbList` на страницах калькуляторов — из той же цепочки, что видимые крошки
    (`calculatorCrumbs` в `src/lib/breadcrumbs.ts`; разметку выводит сам `Breadcrumbs.astro`);
  - `sitemap.xml` — главная, каталог `/kalkulyatory/` и только калькуляторы со статусом `available`, абсолютные адреса,
    без `lastmod` (честной даты изменения нет);
  - в `robots.txt` — строка `Sitemap: https://домен/sitemap.xml`.
- `robots.txt` есть всегда: `User-agent: *`, `Allow: /`; директивы `Host` нет (устарела).
- `sitemap.xml` и `robots.txt` пишет хук сборки (`src/integrations/seo-files.mjs`, D-021).
- Open Graph-изображение `public/og.png` пересоздаётся командой `npm run og:image` из шаблона
  `scripts/og/og-image.html` (токены дизайн-системы, логотип, название и подпись).
- Страница 404 — `noindex`, без canonical.
- Нет ссылок на несуществующие страницы: карточки «Скоро» не являются ссылками.
- Один `h1` на странице, иерархия заголовков h1 → h2 → h3.

## Как включить при публикации

1. Задать переменную окружения `SITE_URL=https://<домен>` в настройках сборки на хостинге (без пути и слэша
   в конце пути — только адрес сайта) и собрать сайт `npm run build`.
2. Проверить на опубликованном сайте `/robots.txt`, `/sitemap.xml` и canonical на нескольких страницах.
3. Добавить сайт в Яндекс Вебмастер и Google Search Console и отправить туда `https://<домен>/sitemap.xml` —
   **действия пользователя**.

Локально режим с адресом проверяется так: `SITE_URL=https://example.com npm run check`, затем
`SITE_URL=https://example.com npm run ui:check` (так же это делает CI).

## Для каждой страницы калькулятора

- `title`/`description` из `seo` каталога.
- Структура: H1 с запросом → калькулятор → результат → «Как считается» (формула) → советы/FAQ.
- Микроразметка `BreadcrumbList` — при заданном `SITE_URL`; `FAQPage` не используется (D-011).
- Перелинковка: блок «Другие калькуляторы» после FAQ (до 4 ссылок, `getRelatedCalculators`) и «Все калькуляторы →».

## Перелинковка и навигация

- Каталог `/kalkulyatory/` — все опубликованные калькуляторы по категориям (только категории с калькуляторами,
  якорь раздела `#<id категории>`), поиск по каталогу. H1 «Строительные калькуляторы онлайн»; description
  собирается из коротких названий калькуляторов, при длине больше 160 символов — без перечня.
- Крошки: калькулятор — «Главная → Калькуляторы (`/kalkulyatory/`) → название»; каталог — «Главная → Калькуляторы».
  JSON-LD `BreadcrumbList` строится из тех же элементов (D-011).
- «Другие калькуляторы» на каждой странице калькулятора: только опубликованные, без текущего; сначала той же
  категории, затем остальные; по порядку каталога, начиная со следующего за текущим и по кругу — так каждый
  калькулятор получает ссылки с одинакового числа страниц (D-022).
- Меню шапки и подвала: «Калькуляторы» (`/kalkulyatory/`, `aria-current="page"` на каталоге и калькуляторах)
  и «О сервисе» (якорь главной). В подвале — короткие названия всех опубликованных калькуляторов.
- Главная: популярные — только опубликованные калькуляторы и «Все калькуляторы →»; раздел «Категории» —
  только при двух и более категориях с калькуляторами (сейчас одна — раздела нет, D-022).
- `sitemap.xml`: главная, каталог и опубликованные калькуляторы (8 адресов при шести калькуляторах).
- Уникальный текст, без переспама ключевыми словами.
