# CLAUDE.md — правила работы над «ДомРасчётом»

«ДомРасчёт» — бесплатный русскоязычный сайт калькуляторов для ремонта и строительства.
Стек: Astro 7 + TypeScript (strictest), статическая генерация. Подробности — в `docs/`.

## Среда

- Работа ведётся в облачном временном контейнере Claude Code (часто с телефона).
  **Всё, что не отправлено в GitHub, теряется.** Проверенные изменения коммитить и пушить в рабочую ветку.
- Node.js ≥ 22.22.0 (см. `.nvmrc`), пакетный менеджер — npm, lock-файл `package-lock.json` коммитится.
- Не делать merge в `main` и не переписывать историю без явного запроса пользователя.

## Команды

| Команда             | Что делает                                                    |
| ------------------- | ------------------------------------------------------------- |
| `npm ci`            | установка зависимостей строго по lock-файлу                   |
| `npm run dev`       | dev-сервер Astro                                              |
| `npm run typecheck` | `astro check` — типы в `.ts` и `.astro`                       |
| `npm run lint`      | ESLint                                                        |
| `npm run format`    | Prettier (запись), `npm run format:check` — только проверка   |
| `npm test`          | Vitest                                                        |
| `npm run build`     | статическая сборка в `dist/`                                  |
| `npm run check`     | всё сразу: типы → линтер → формат → тесты → сборка (как в CI) |
| `npm run ui:check`  | Playwright-проверка главной (390 px и 1440 px), нужна сборка  |

## Правила

1. **Сначала контекст.** Перед работой прочитать этот файл, `docs/ROADMAP.md` и относящиеся к задаче документы.
   Крупные изменения (новый раздел, смена архитектуры, новые зависимости) — сначала план, затем реализация.
2. **Не менять несвязанные файлы.** Правка должна касаться задачи; попутные улучшения — отдельно и с упоминанием.
3. **Не удалять пользовательские данные** и чужие файлы. Перед удалением/перезаписью — посмотреть, что там.
4. **Запускать проверки.** Перед коммитом — `npm run check`; при изменениях интерфейса — ещё `npm run ui:check`.
5. **Честные отчёты.** Не заявлять о прохождении тестов, которые не запускались или упали. Различать
   «реализовано», «проверено», «проверено частично», «не проверено».
6. **Обновлять документацию.** После этапа — `docs/ROADMAP.md` (статус) и `docs/CHANGELOG.md`;
   значимые решения — в `docs/DECISIONS.md`.
7. **Проверять изменения перед коммитом:** `git status`, `git diff`; в коммит не должны попасть секреты,
   `.env`, `dist/`, `node_modules/`, скриншоты `.ui-check/`.
8. **Сохранять в GitHub.** Среда временная: после проверок — коммит и `git push -u origin <рабочая-ветка>`.
9. **Не создавать платные ресурсы**, не публиковать сайт, не подключать рекламу, БД и регистрацию без решения пользователя.

## Правила кода

- Весь интерфейс — на русском, UTF-8. В `<head>` всегда `<meta charset="utf-8">` (это делает `BaseLayout`).
- Формулы расчётов — только в чистых функциях в `src/lib/` (без DOM и Astro) с тестами Vitest рядом (`*.test.ts`).
  Тесты проверяют реальные значения, а не «что-то вернулось».
- Каталог калькуляторов — единый источник данных: `src/data/calculators.ts`. Статус `available` ставится
  только вместе с готовой страницей по `path`. Карточки со статусом «Скоро» не являются ссылками.
- Не изображать несуществующие функции, не добавлять фиктивные страницы и ссылки.
- Стили — через дизайн-токены из `src/styles/tokens.css` (`docs/DESIGN_SYSTEM.md`), без «сырых» цветов в компонентах.
- JavaScript на клиенте — только где без него нельзя (поиск, меню). Без UI-фреймворков и тяжёлых библиотек.
- Новые зависимости — только при явной необходимости, с записью в `docs/DECISIONS.md`.
- Мобильная версия обязательна: проверять ширину 390 px, отсутствие горизонтальной прокрутки, зоны нажатия ≥ 44 px.
